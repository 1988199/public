# AGENTS.md

本文件是本仓库所有长期维护者和自动化代理必须遵守的规则。规则适用于整个仓库；子目录若有更具体的 `AGENTS.md`，可补充但不得降低这里的数据与安全要求。

## 项目边界

1. 本项目是 ERPNext V16 中文单容器发行版，不是业务实施仓库。
2. 只维护构建、运行、升级、扩展接口和中文技术文档；不得添加企业业务数据。
3. Frappe、ERPNext、HRMS 和 CRM 必须来自各自官方 GitHub 仓库。不得把上游源码复制进本仓库长期维护。
4. 不直接修改上游核心源码。中国本地化和会计能力必须作为独立 Frappe App 接入。
5. 单容器是当前明确约束；改变部署拓扑必须先新增中文架构决策记录。

## 版本与升级

1. 仅跟随 Frappe/ERPNext `version-16`；不得无意切到 `develop` 或 V17。
2. 正式发行必须将所有 App 固定到已验证标签或提交 SHA，并记录基础镜像与成品镜像 digest。
3. 禁止在生产容器内执行 `bench update`；升级必须通过可重建的新镜像完成。
4. App 清单变更必须同时更新兼容性说明，并验证空站点安装和已有站点迁移。
5. 数据库迁移前必须有可恢复备份；回滚应恢复代码、数据库和 sites 的同一时间点。

## 数据与秘密

1. 禁止提交 `.env`、`sites`、数据库、备份、日志、附件、私钥、令牌或私有 App 清单。
2. 示例只能使用虚构名称与明显占位值；不得从真实企业数据改写或“脱敏”后提交。
3. 私有 App 通过 BuildKit secret/SSH 接口获取，凭据不得进入 `ARG`、镜像层、构建日志或 Git 历史。
4. 发现疑似秘密或业务数据时立即停止提交，先隔离并通知维护者；不要自行扩散内容。

## 代码与文档

1. 面向使用者和运维人员的文档使用简体中文；代码标识符可使用英文。
2. Shell 脚本使用 `set -Eeuo pipefail`，路径和变量必须正确引用。
3. 改动保持小而可审查，优先配置和扩展点，不维护不可追踪的容器内手工状态。
4. 新增运行路径必须补充健康检查、持久化边界、失败行为和升级说明。
5. 不添加业务初始化脚本、演示公司或默认真实口令。

## 简体中文本地化

1. 不直接修改 Frappe、ERPNext、HRMS 或 CRM 的翻译文件；补充译文必须由独立本地化 App 承载。
2. 引用官方历史语言包时必须固定标签和 SHA-256，并记录上游缺陷及移除条件。
3. App 版本升级必须统计 `zh.po` 的语言标识、空译文数量，并验证登录页、Desk、ERPNext、HRMS 和 CRM 的主要入口。
4. 翻译内容只能是公共 UI 元数据；禁止把公司、客户、员工、物料或其他业务数据作为“翻译”提交。
5. 内部标识符、API 名、DocType 名和数据库键不得为了界面汉化而重命名。

## 验证门禁

提交前至少执行：

```text
python scripts/validate.py
docker compose --env-file .env.example config --quiet
```

涉及镜像构建、入口脚本、依赖版本或 App 清单时，还必须构建镜像，并在临时 volume 上完成首次启动、健康检查、App 列表和无业务数据验证。未实际完成的验证必须在交付说明中明确标注，不得声称成功。

涉及中文包、翻译补丁或上游 App 版本时，还必须执行关键译文烟雾测试，至少覆盖登录、保存、提交、取消、搜索和 CRM 权限提示。
