# GitHub 自动构建镜像

构建完全在 GitHub Actions 中运行，无需本机 Docker Desktop。

## 触发方式

- 向 `main` 或 `agent/**` 分支提交构建相关文件，自动构建、测试和发布。
- 打开仓库 Actions →「构建并测试 Docker 镜像」→ Run workflow，选择维护的发布分支后运行，也会测试并发布。
- 每天定时检查 Frappe、ERPNext、HRMS 的 V16 官方稳定版及 CRM 的 V1 官方稳定版；只接受正式 GitHub Release，拒绝版本回退或同名标签 SHA 变化。
- 对 `main` 手动运行时也会检查官方版本。检测到新版本后先更新临时构建清单；镜像通过完整测试并发布后，才将固定版本和官方提交 SHA 写回仓库。
- 官方版本未变化且 `latest` 已存在时，定时任务跳过重复构建。

## 验证与获取

构建后依次执行普通空站点安装、未传 `SITE_NAME` 的手动启动、应用版本、服务、科目模板、关键中文译文、`localhost` 页面与静态资源检查。全部通过后才上传 GHCR。

成功后在运行摘要中复制 `docker pull` 命令。镜像包为 `ghcr.io/1988199/erpnext-single`，每次运行提供独立 `build-运行编号-尝试次数` 标签、源码 `sha-提交编号` 标签、带 `V` 前缀的具体版本标签（如 `:V16.36.0`）和镜像 digest。`main` 发布 `:latest`。不再发布纯数字版本标签（如 `:16.36.0`）。相同提交重跑时 SHA 与版本标签可能更新，精确复现请使用 digest 或本次独立构建标签。

发布分支也更新具体版本标签；仅 main 更新 `latest` 和 `v16` 滚动标签。运行的 Artifacts 中提供镜像说明，不包含大型离线 tar 或企业数据。

使用 GitHub 内置 GITHUB_TOKEN 发布和提交通过测试的上游版本锁。流程不会自动部署、修改当前站点或处理真实企业数据。部署前仍须备份并验证真实业务流程。
