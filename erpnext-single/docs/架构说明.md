# 架构说明

## 运行边界

一个容器内包含以下进程：

```text
Nginx :80
├── Gunicorn :8000 -> Frappe / ERPNext / HRMS / CRM
└── Socket.IO :9000

Supervisor
├── MariaDB :3306（仅容器内回环地址）
├── Redis :6379（仅容器内）
├── Gunicorn
├── Socket.IO
├── RQ Worker
├── Scheduler
└── Nginx
```

只有 Nginx 的 80 端口对外暴露。数据库、Redis 和应用后端均绑定容器内部，不由 Compose 发布端口。

## 数据边界

| 卷 | 容器路径 | 内容 |
| --- | --- | --- |
| `database` | `/var/lib/mysql` | MariaDB 数据文件 |
| `redis` | `/var/lib/redis` | Redis AOF 与队列状态 |
| `sites` | `/home/frappe/frappe-bench/sites` | 站点配置、公开及私有附件 |
| `logs` | `/home/frappe/frappe-bench/logs` | Bench 日志 |

上述路径全部被 `.gitignore` 和 `.dockerignore` 排除。镜像层只包含应用源码、静态资源和运行配置。

完整决策、初始化状态机和发布门禁见 [Docker 基础架构设计](Docker基础架构设计.md)。

## 源码与版本边界

- Frappe：`Dockerfile` 的 `FRAPPE_REF`，当前固定为 `v16.35.0`。
- ERPNext：`docker/apps.json`，当前固定为 `v16.36.0`。
- CRM：`docker/apps.json`，当前固定为 `v1.85.0`。
- HRMS：`docker/apps.json`，当前固定为 `v16.20.0`，并在 ERPNext 之后安装。
- 中国小企业会计准则公共元数据：仓库内独立 `china_sme_accounting` App，当前版本 `0.2.0`。
- 企业专属会计扩展：仅通过构建密钥传入，不进入公共清单。

ERPNext V16 的科目模板扫描器仅扫描 ERPNext 自身的 `verified` 目录，尚无跨 App 注册钩子。镜像构建时只创建一个从该目录指向 `china_sme_accounting` 准则 JSON 的符号链接，不修改 ERPNext Python 源码。每次升级 ERPNext V16 时必须验证该扫描路径、模板选择和虚构公司建账烟雾测试。

大版本分支适合日常集成验证，但正式发行必须记录基础镜像 digest、Frappe/ERPNext/HRMS/CRM 提交 SHA 和最终镜像 digest，保证可追溯与可回滚。

## 首次启动

入口脚本只执行基础设施初始化：初始化 MariaDB、创建空 Frappe 站点、安装镜像内 App、执行迁移，然后切换到 Supervisor。安装 App 时会加载公共准则模板，但不会创建公司或实际科目，不会导入客户、供应商、用户、期初余额或凭证。只有用户新建公司并显式选择“中国小企业会计准则”后，ERPNext 才为该公司创建 66 个编号科目。
