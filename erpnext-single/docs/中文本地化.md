# 简体中文本地化

## 当前问题

此前验证的 Frappe `v16.31.0` 官方 `frappe/locale/zh.po` 被错误标记为繁体中文，且几乎全部译文为空。Frappe 官方缺陷 [#41461](https://github.com/frappe/frappe/issues/41461) 已记录从 `v16.29.0` 开始出现的简体中文回退问题。升级到 `v16.35.0` 后通过 CI 输出各 App 的 `zh.po` 语言标识和空译文统计，并检查关键译文及页面静态资源；继续使用下述临时基线，移除前还需人工核查界面覆盖率。

ERPNext、HRMS 和 CRM 自带的简体中文包仍会照常加载。其中 ERPNext 和 CRM 存在部分未翻译的新文本，本发行版通过独立 App 补充高频登录、Desk 和 CRM 操作词，不直接修改任何上游 App。

## 构建策略

1. `docker/translations.json` 固定引用 Frappe 官方 `v16.24.4` 的最后一个已验证简体中文包。
2. 构建过程必须校验下载内容的 SHA-256，校验失败立即终止。
3. `docker/install_translations.py` 只提取非空、非模糊译文，并转换为 Frappe App 标准的 `translations/zh.csv`。
4. `zh_overrides.csv` 保存当前 V16 新界面所需的发行版补充译文；只允许公共 UI 文本，不得包含企业数据。
5. 中国本地化 App 最后安装，因此其译文会覆盖上游空值或不准确译文；上游源码文件保持不变。

官方旧版翻译文件遵循 Frappe 的 GPL-3.0 许可，仅在镜像构建时从官方 GitHub 获取并随 GPL ERPNext/Frappe 运行环境分发，不复制进本仓库。

## 升级维护

每次更新 Frappe、ERPNext、HRMS 或 CRM 时必须：

1. 检查四个 App 的 `locale/zh.po` 语言标识及空译文数量。
2. 运行空站点镜像测试，确认登录、保存、提交、取消、搜索和 CRM 权限提示均为中文。
3. 若 Frappe 官方已修复 #41461，应优先移除旧版官方包回填，只保留仍有必要的发行版补充译文。
4. 更新翻译源时同时更新 URL、SHA-256、最小有效条目数和本文件说明。

## 边界

- DocType、字段名、状态值等可翻译元数据通过语言包显示中文，不重命名数据库内部标识符。
- 公司名、客户名、物料名、员工姓名等业务内容不会自动翻译，也不得写入公共镜像。
- 专有名词如 ERPNext、Frappe、CRM、API、OAuth 可以保留英文；界面操作和用户提示应优先使用简体中文。
