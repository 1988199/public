# 中国小企业会计准则 App 扩展接口

App 的领域模型、报表、校验、权限和分阶段实现见 [中国小企业会计准则 App 设计](中国小企业会计准则App设计.md)。本文件只描述发行版如何安全地把该 App 注入镜像。

## 约束

中国会计 App 必须是独立 Frappe App，不直接修改 `frappe`、`erpnext` 或 `crm` 上游源码。公共仓库不保存私有仓库地址、访问令牌、许可证文件、企业科目或初始化数据。

## 清单格式

复制 `docker/apps.extra.example.json` 到仓库外的安全位置，设置真实 `name`、`url` 和不可变 `ref`。`ref` 推荐使用已签名标签或完整提交 SHA。

构建时通过 BuildKit secret 注入：

```powershell
docker build `
  --secret id=extra_apps,src=C:\secure\apps.private.json `
  --build-arg FRAPPE_REF=v16.35.0 `
  -t erpnext-v16-cn:local .
```

该清单只在单个构建步骤可见。镜像最终仅记录需要安装的 App 名称，不记录私有 URL、ref 或凭据。私有 Git 认证应使用 BuildKit SSH/secret 能力扩展，禁止把令牌写进 URL 或 `ARG`；当前骨架尚未启用私有 Git 认证实现。

## App 契约

会计扩展在接入前至少应满足：

1. 声明兼容 Frappe/ERPNext V16。
2. 所有 DocType、Custom Field、Workspace 和 Fixture 均由 App 迁移管理。
3. 默认安装不得创建真实企业、账户、用户或交易数据。
4. 示例科目或演示数据必须由显式命令启用，并与生产安装分离。
5. 卸载、迁移和备份恢复路径有自动化测试。
6. 对 ERPNext 核心对象的覆盖尽量使用 hooks 和扩展机制，不维护长期源码补丁。
