# 安全与数据边界

## 公共仓库允许内容

- Dockerfile、Compose、Supervisor、Nginx 和启动脚本。
- 官方公开 App 的仓库地址和公开版本引用。
- 虚构域名、占位密码及不对应真实企业的示例。
- 架构、开发、升级和维护文档。

## 禁止内容

- `.env`、真实密码、令牌、SSH key、证书和私有仓库地址。
- 数据库文件、SQL dump、备份、站点配置、日志和附件。
- 公司名称、税号、银行账号、联系人、客户、供应商、科目余额、凭证等业务数据。
- 从生产环境复制的截图、错误日志或脱敏不充分的测试样本。

## 发布前检查

执行 `python scripts/validate.py`，并使用秘密扫描工具检查完整 Git 历史。生产环境还应在外层反向代理终止 TLS，限制管理入口，定期更新基础镜像，并将备份加密保存到独立故障域。

当前测试阶段经维护者明确例外授权，镜像和 `.env.example` 暂时为数据库 root 与首次建站的 ERPNext `Administrator` 提供默认密码 `Pass1234`。入口脚本使用任一测试默认值时会输出警告，部署者可通过 `DB_ROOT_PASSWORD` 和 `ADMIN_PASSWORD` 覆盖。`ADMIN_PASSWORD` 只用于创建新站点，不会重置已有站点。此例外不适用于正式发行或任何对外联网环境；进入正式发布前必须移除默认值并轮换所有已使用该密码的数据卷。

企业初始化数据的仓库、制品、秘密、执行和审计边界见 [私有企业初始化方案](私有企业初始化方案.md)。公共仓库只保留初始化清单 Schema，不提供企业样例包。
