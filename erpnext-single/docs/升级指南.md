# ERPNext V16 升级指南

## 原则

升级通过“新镜像 + 原数据卷”完成，不在运行中的容器里执行 `bench update`。任何发布都必须可由源码清单重建。

当前候选版本组合见 [版本清单](版本清单.md)。ERPNext 与 Frappe 的发布编号并不要求相同；应以各自官方标签和依赖声明为准。本次 ERPNext 为 `v16.36.0`、Frappe 为 `v16.35.0`。CI 在临时卷中检查空站点启动；真实业务站点仍须在同一时间点备份数据库和文件，并在副本上完成业务回归后切换镜像。

## 建议流程

镜像内 `/opt/erpnext-assets` 保存本次构建的静态资源快照，入口脚本会将其同步到 `sites/assets`。这是升级的必要步骤：旧持久卷的资源清单可能仍引用上一版 CSS/JS，单独运行 `bench migrate` 不会更新它们。同步仅处理公共构建产物，不处理各站点的配置、附件和数据库；无需在启动时重新编译。

1. 阅读 ERPNext V16、Frappe V16、HRMS V16 与 CRM 的 release notes 和迁移说明。
2. 在升级分支更新 `FRAPPE_REF` 和 `docker/apps.json`；候选发布使用标签或提交 SHA。
3. 构建候选镜像并记录上游提交、基础镜像 digest 和镜像 digest。
4. 从生产备份恢复到隔离环境，不直接用生产卷试升级。
5. 启动候选镜像；入口脚本自动执行 `bench migrate`。
   若新镜像的公共 App 清单增加了 App，入口脚本会按清单顺序先为已有站点安装缺失 App，再运行迁移；删除 App 不会自动卸载。
6. 验证登录、ERPNext 核心单据、HRMS、CRM、队列、定时任务、打印及中国会计扩展。
   中国会计扩展必须验证：App 已安装、中国公司可看到“中国小企业会计准则”、虚构公司能创建 66 个编号科目、5001 为 Income、5403 为 Expense。
   简体中文必须验证：登录页、Desk 常用按钮和 CRM 高频操作不回退为英文；同时检查各 App `zh.po` 的语言标识和空译文数量。
7. 完成数据库恢复演练后再发布；保留旧镜像和升级前备份。

## 回滚边界

数据库迁移通常不可通过换回旧镜像安全回滚。回滚必须同时恢复升级前数据库与 `sites` 备份，不能让旧代码直接读取已迁移的数据结构。

## V17 边界

本仓库当前只接受 V16 的补丁和次版本更新。升级 V17 必须建立独立设计决策、兼容性矩阵和迁移分支，不得在普通依赖更新中顺带完成。
