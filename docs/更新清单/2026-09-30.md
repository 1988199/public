## ERPNext 与 Frappe

ERPNext 16.37.0 的主要变化：

- 优化物料关联字段搜索，使用 FTS5 三元组索引。
- 修正单位整数校验、序列号和批次预留，避免重复预留或使用其他单据已预留的批次。
- 修正生产计划跨仓库预留、完工后释放预留、工单退料与已转移物料数量的计算。
- 修正虚拟 BOM 展开数量、工序卡关联范围及生产损耗导致无成品时的校验。
- 修正委外服务成本币种换算，以及批次和序列号退回的估价。
- 加强发票操作、估价和来源单据的权限检查；修正银行对账、采购登记表与库存重记账的若干问题。

来源：[ERPNext 16.37.0 官方说明](https://github.com/frappe/erpnext/releases/tag/v16.37.0)，[16.36.1 → 16.37.0 完整差异](https://github.com/frappe/erpnext/compare/v16.36.1...v16.37.0)。

Frappe 16.36.0 新增可配置的 Automation 规则，以及通知使用 Email Template 的能力；改进搜索索引、多选表格字段、时间和日期字段、应用图标与文件权限检查。

兼容性变化：Jinja 模板不再暴露由 hook 模块导入的函数。使用此类自定义打印格式或模板的站点，应检查模板函数的定义方式后再升级。

来源：[Frappe 16.36.0 官方说明](https://github.com/frappe/frappe/releases/tag/v16.36.0)，[16.35.0 → 16.36.0 完整差异](https://github.com/frappe/frappe/compare/v16.35.0...v16.36.0)。

CRM 1.85.1 和 HRMS 16.20.0 本次保持已有版本。CRM 1.85.1 已包含附件、筛选器、邮件回复账号和通话录音等修复；详情见 [官方说明](https://github.com/frappe/crm/releases/tag/v1.85.1)。

## EspoCRM

10.0.9 修复分配通知未显示名称，以及数组字段的个人数据擦除不生效两个问题。

来源：[EspoCRM 10.0.9 官方说明](https://github.com/espocrm/espocrm/releases/tag/10.0.9)。

## Twenty

本次从 2.41.0 升到官方应用稳定版 2.43.0；`sdk/v2.42.0` 是 SDK 发布，不能作为 CRM 应用版本选择依据。

- 工作流转为使用 core ID，并完善后台执行、私有工作流、分类节点与同步行为。
- 记录创建表单成为默认创建入口；附件、工作区图标和头像使用直接上传。
- 增加工作区文件、记录、邮件与工作流用量限制的支持，实际可用能力取决于配置、功能开关及上游许可。
- 改进 AI 对话、Microsoft Teams 集成、机会看板、图表显示和 CSV 导出进度。
- 收紧会话、工作区、权限及应用接口检查。

兼容性变化：应用文件上传接口和工作流 API 有调整。使用自定义应用、SDK 或工作流集成的站点，应先核对上游变更。

来源：[Twenty 2.43.0 官方说明](https://github.com/twentyhq/twenty/releases/tag/twenty/v2.43.0)，[2.41.0 → 2.43.0 完整差异](https://github.com/twentyhq/twenty/compare/twenty/v2.41.0...twenty/v2.43.0)。

## 自动脚本变化

- ERPNext：保留带大写 `V` 的版本标签和 `latest`，继续停止纯数字版本标签；增加上一稳定镜像空站点的备份与升级测试；修正构建产物上传目录。
- EspoCRM：从官方 GitHub 稳定发布选择版本，并验证对应官方 Docker 镜像存在；增加网页、中文配置及容器重建后持久化测试，全部通过后才发布。
- Twenty：网页测试明确发送 `Accept: text/html`，适配新版前端导航检查；继续测试 PostgreSQL、Redis、文件、密钥持久化与 Worker 自动恢复。
- 三个流程：版本记录推送增加 rebase 和重试，降低同时发布时互相阻塞的概率；每天检查稳定版，未变化且标签存在时跳过重建。
- ERPNext 每天 10:43、EspoCRM 每天 10:17、Twenty 每天 10:43 检查（UTC+8）。GitHub 定时任务可能延迟执行。
