# 运行修订20261026.1：等效低开销改进

本修订为源码候选，只有完整测试通过且ERPNext版本前进时才正式发布；不自动部署，不修改现有卷。应用版本、SQLite功能、单容器拓扑、默认初始化参数、权限及迁移门禁不变。

## 全包检查后的取舍

检查范围包含Docker构建、入口、依赖等待、健康检查、应用就绪、手动与自动备份、加密、副本、保留策略、日志轮转、Supervisor、Compose、发布脚本及测试。

| 路径 | 改进 | 保持的行为 |
| --- | --- | --- |
| 健康检查 | 每轮10次Supervisor客户端调用合为1次 | 仍每15秒检查全部10项；缺失、重复、停止均失败；数据库、Redis、HTTP、应用导入、心跳和备份检查不减少 |
| 备份调度 | Event等待取代每秒空转；空闲最多每分钟核对墙钟，关闭时等待信号 | 原周期、启动延时、有限重试、互斥和超时；信号可立即唤醒 |
| 附件验证 | 单次流式解压同时检查tar成员和gzip完整流，元数据不全量缓存 | 每个附件内容完整读取；tar结束后仍读至gzip EOF并验证尾部CRC |
| 加密回读 | 加密读取时计算摘要，认证回读时流式计算并比对 | 同一AES-256-GCM文件格式、全流认证及SHA-256一致性；认证失败不得提交 |
| 磁盘临时文件 | 加密校验不再生成、写入和重读整份verify.tar | 不改变用户主动解密命令及恢复文件内容 |
| 普通重启 | 公共连接配置一致时跳过4次Bench设置命令 | 首次初始化或配置不同仍通过原命令修复，站点及迁移规则不变 |
| 构建 | 系统依赖安装放到运行脚本COPY之前，合并配置层 | 依赖和编译选项不减少，可复用未变依赖层 |

不通过减少Web进程、合并长短任务队列、关闭备份、降低日志/健康检查频率、缓存健康结果或缩减数据库持久化保障来节省资源。MariaDB、Redis、Frappe及各App核心源码均未修改。静态资源仍沿用原同步机制，避免把时间戳相同但内容不同的资源错误跳过。

## 恢复兼容修正

官方附件生成器根据 `get_site_path` 创建tar路径。使用绝对sites路径会把整个路径层级放入包内，导致官方restore后附件不在预期位置。自动备份及迁移前备份改为Bench标准相对路径初始化；增加归档路径断言和独立容器恢复测试。已有备份不重写、不删除；曾用旧候选代码生成的绝对路径附件包须在隔离环境核实路径后恢复，不能只凭数据库恢复成功判定附件已恢复。

## 合成微基准

2026-10-26，在隔离Linux容器、相同Python/密码学依赖下比较公共提交 `f716866` 与本修订。每项3次，取墙钟中位数。Supervisor只管理10个sleep进程，不运行数据库或ERP服务；附件为16 MiB随机合成数据。没有使用任何企业数据或现场容器。

| 测量 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 一轮10项Supervisor状态查询 | 2.5023秒 | 0.2463秒 |
| 加密、认证回读及摘要校验 | 0.0897秒 | 0.0675秒 |
| 管理客户端调用数/健康检查 | 10 | 1 |
| 加密校验新增明文写入量 | 16 MiB | 0 |

基准测的是上述局部路径，不是整机CPU、内存、ERP页面速度或生产业务吞吐量的降幅。磁盘缓存、CPU、Docker宿主及附件大小都会影响实测；实际高负载需另做现场授权测试。每15秒一轮的管理客户端调用由每小时2400次减为240次，其他健康检查不计入此数字。

可复测：在Linux环境中，把仓库只读挂载到容器，使用现有Frappe Python运行 `tests/benchmark_runtime.py --baseline f716866`。需要该公共Git基线、Supervisor与密码学依赖；脚本只管理自身临时Supervisor及合成文件。离线回归见 `tests/test_runtime_ops.py`，完整初始化/恢复/升级验证见 `tests/smoke.sh`。

## 部署与回退

源码优化不代表已发布镜像，也不代表现场已经应用。正式发布仍受ERPNext版本前进门禁约束；不重发当前同版本标签。部署前保留完整恢复点并在副本验证；不在运行容器中手动覆盖维护脚本。数据库发生迁移后，回退需要匹配的代码、数据库、配置及附件恢复点，不能只换回镜像。
