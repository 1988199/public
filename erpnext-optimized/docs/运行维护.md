# 备份、日志、就绪与停机

本页适用于运行修订 **20261024.1 及以后**。当前源码候选会独立构建验证，但不替换已发布的同 ERPNext 版本镜像；正式功能随下一次 ERPNext 新版本发布带入。请核对镜像内 `/opt/erpnext-runtime/manifest.json`，不能因为更新了 Compose 就认为旧镜像已具备这些功能。

## 单一备份服务

Supervisor 管理 `backup-service`，以 frappe 身份运行。默认启动60秒后尝试首次完整备份，此后每6小时一次；重启按上一次成功时间继续，不每次重复备份。新镜像构建时只移除旧 Bench backup cron 条目，保留其它条目，不启动 cron，也不增加第二套 Frappe 定时任务。

备份包含完整数据库、公共/私有附件、站点配置、公共站点配置及应用版本清单。生成后验证数据库压缩流和完成标志、全部附件压缩流、配置 JSON 和组件 SHA-256；外部副本另校验清单。默认数据库备份不按用户设置的表排除项删减。

这不是“写入期间跨数据库与文件的原子快照”。需要严格同一恢复点时，应先进入维护并停止业务写入；真实账套仍须独立恢复演练。应用版本清单也不等于应用源代码备份：私有 App、依赖、hooks及构建资源必须另有可重建的部署包。

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| BACKUP_ENABLED | 1 | 0可关闭；如由宿主机统一备份，应关闭容器内调度，避免重复 |
| BACKUP_INTERVAL_SECONDS | 21600 | 周期，最小60秒 |
| BACKUP_START_DELAY_SECONDS | 60 | 首次启动延时，可为0 |
| BACKUP_RETRIES | 3 | 每周期最多尝试次数，范围1至5 |
| BACKUP_TIMEOUT_SECONDS | 900 | 单次备份上限，范围30至86400秒 |
| BACKUP_RETENTION_DAYS | 7 | 本地保留天数，至少保留最近两份校验完整的备份 |
| BACKUP_COPY_DIR | 空 | 已预先挂载且frappe可写的容器外副本目录 |
| BACKUP_COPY_RETENTION_DAYS | 30 | 外部副本保留天数，同样至少保留两份 |
| BACKUP_ENCRYPTION_KEY_FILE | 空 | 可读密钥文件路径，内容为32个随机原始字节，不是32字符口令 |

本地默认目录是 `sites/站点/private/automatic_backups`，不使用或清理用户原 `private/backups`、迁移备份及其它备份目录。只有专用命名且清单完整的本工具备份会按保留期清理。普通失败立即清理本次半成品；强制终止遗留的半成品必须有本工具所有权标记、匹配命名并超过两天才清理。校验失败、无标记或未知目录不自动删除。

本地未配置密钥时采用仅所有者可读的明文恢复包；配置密钥后使用分块 AES-256-GCM 加密并认证回读。若站点已要求加密但没有提供运行密钥，备份失败并报警，不悄悄降为明文。

配置外部副本时必须同时配置密钥，输出为加密包；不在命令行、日志或状态中输出密钥和数据库口令。请把密钥保存在独立恢复位置，勿放进备份包或公共仓库。丢失密钥无法恢复，不能用随机新密钥解密旧备份。

### 外部副本接口

例如将独立备份存储挂到 `/runtime-copy`，只读密钥文件挂到 `/run/secrets/runtime-backup.key`，再设置上述两个路径变量。镜像会在目的地下建立 `站点/runtime-v1/备份编号`，暂存、验证后才改名为完整备份。需要确认frappe能读密钥并写目的地，不能放宽到公共可写目录作为生产方案。

镜像无法识别宿主机磁盘或灾难恢复域：另一个Docker卷、同一磁盘目录、网络存储、异地主机不能视为等价。同主机卷只解决容器重建，不防整机或磁盘故障。操作者负责真正的外部/异地映射、容量、访问控制和恢复演练。需要云存储时可挂载合适的受控文件系统或由外部备份系统采集；镜像不内置云账号或网络凭据。

### 状态与告警

状态保存在上述私有目录的 `status.json`，包含开始时间、最后成功、失败次数、错误类型及副本是否已配置，不包含连接凭据。可运行：

```sh
docker exec -u frappe 容器名 /home/frappe/frappe-bench/env/bin/python /opt/erpnext-runtime/backup_service.py status
```

有限重试全部失败会写 `state=failed` 并向容器日志输出通用告警；健康检查也会失败。长期未成功同样触发健康异常。外部监控应订阅Docker健康状态及该状态文件；本机制不自动发送邮件，也不擅自重启或重建容器。

首次备份有延时，初始健康不等于已产生恢复点。应检查 `last_success` 和副本存储；不能只看Supervisor进程为RUNNING。定时任务使用非阻塞文件锁防重入，手工调用本工具也受同一把锁约束；其它独立备份工具不受这把锁管理。

加密包可用同一密钥通过 `backup_service.py decrypt --source 包路径 --target 新tar路径` 解密；认证失败不提升临时输出，也不覆盖已有目标。解包前检查路径，再使用官方 `bench restore` 恢复数据库和两类附件。站点配置保留原加密密钥及业务配置，但数据库连接、Redis等环境相关字段须按恢复目标审核；不要盲目覆盖目标连接。源镜像摘要、私有应用部署包和密钥也必须可取得。

## 应用部署与任务就绪

Web和worker启动前检查数据库已安装的所有应用及其hooks能导入；可用 `REQUIRED_APPS` 指定必须存在的应用（逗号或空格分隔）。私有应用的懒加载依赖应通过 `REQUIRED_MODULES` 列出关键模块导入路径，不能把根包可导入当作所有报表和控制器均可用。`REQUIRED_ASSET_PATHS` 可列出相对 `sites/assets` 的必要文件路径；禁止绝对路径和父目录跳转。

可选 `DEPLOYMENT_READY_FILE` 指向部署入口提供的JSON文件，只有 `ready` 为true才放行。部署时应先撤销该标记并停Web写入、调度和worker，完成应用代码、依赖、hooks、资源和迁移验证后才更新标记。单纯把数据库和sites卷接入新容器，不代表缺失的应用代码会自动恢复。

运行期健康检查包含应用导入、实际RQ worker心跳与队列统计；`VERIFY_QUEUE_HEARTBEAT=0`可关闭该扩展检查，`WORKER_HEARTBEAT_MAX_AGE_SECONDS` 默认300秒、最低30秒。心跳证明当前worker活跃，不是所有业务任务执行成功的验收。调度器仍检查Supervisor进程；业务定时任务另需监控完成时间。

历史失败任务只按队列报告数量，不据此直接判定当前不健康，也不自动清空、重放或重试。异常待办必须另行核实其业务幂等性和授权。

## 日志轮转

Supervisor管理 `logrotate-service`，每60秒执行已安装的logrotate。Nginx文件日志写入持久日志卷下的 `nginx/`，按天或超过10MB轮转，保留7份并压缩，随后发送USR1让Nginx重新打开文件。检查周期内可能暂时超过10MB，这不是磁盘硬配额。

访问日志不记录请求查询参数或认证头。日志本身仍可能包含地址、请求路径等敏感信息，应限制日志卷访问并配置外部采集。Docker标准输出继续使用Compose的local驱动及有界轮转，不改成无限json-file，也不把文件与标准输出进行重复截断。

## 停机契约

Dockerfile只能提供SIGTERM，不能强制Docker Desktop采用某个外层等待时间。Compose显式采用 `STOP_GRACE_PERIOD`，默认600秒；直接创建容器时需显式 `--stop-timeout 600`，或配置同等等待，不依赖通常只有10秒的默认值。

Supervisor按优先级停止日志轮转、Nginx、备份、worker、Web、Redis及数据库。最坏等待应累计考虑备份120秒、worker90秒、Web30秒、Redis30秒、数据库90秒及其它服务，180秒不足以覆盖全部预算。若更改内部stopwaitsecs或允许更长任务，必须同步增加外层宽限；600秒并不意味着任务可无限运行。

备份服务在停机时终止其专属子进程组，未完成的备份不被标记成功。CI用20秒合成长任务验证容器没有10秒提前强杀，并检查数据库正常Shutdown及重启跳过重复迁移。这不替代生产最大任务时长和高负载数据库停机测试。

## 验证与发布边界

候选验证不推送镜像、不改变已发布版本基线。包括离线保留/加密/失败重试测试、全新站点、真实worker心跳、完整备份及加密独立卷副本、数据库和附件的独立恢复容器验证、真实日志轮转和忙worker正常停机。测试数据仅为合成客户和标记文件。

保留SQLite兼容、长短队列分离及显式迁移门禁。不为了消除io_uring兼容提示开放privileged或额外宿主权限。Redis降权暂不纳入本轮，避免未经AOF和既有卷权限验证就改变持久数据所有权。
